# Recall: project handover

Read this first in any new chat about Recall. It explains what the app is, where everything lives, how to build and ship it, and what's been decided along the way.

*Last updated: 25 November 2026 · app shell v1.29.0 · page build 20261125000335*

**Design rules live in `CLAUDE.md`** (what never to do, the design system, how to critique a screen). Read it before any UI change.

---

## 1. What Recall is

Recall (originally called "Error Log") is the user's spaced-repetition flashcard app for the mistakes made in Maths, Physics and Economics. A card holds a question (text and/or several screenshots), *why I got it wrong*, and the correct solution. There are also **Knowledge** cards (question + explanation). Cards are rated Again / Hard / Good / Easy and scheduled with an SM-2-style algorithm.

It runs in three places from **one source file**:

| Where | What it is | How it updates |
|---|---|---|
| **Mac** | Electron app (Apple silicon, arm64) | Downloads `desktop.html` from GitHub by itself and shows "Restart now" |
| **Windows** | Electron app (x64) | Same as the Mac |
| **iPad / iPhone / Android / browser** | Web app on GitHub Pages, added to the home screen | Loads the newest `index.html` whenever it opens; shows "Reload" if it was left open |

Every device syncs through **Supabase** (email + password account, "Turn on sync" in the sidebar).

## 4. Making a change and shipping it (the normal routine)

1. **Edit `src/mistake-deck.html`.** Keep a backup copy first.
2. **Build:** `python3 tools/release.py`. That rebuilds the desktop page and the web files, and stamps them all with one build number (`YYYYMMDDHHMMSS`).
3. **Test** (see §8). At least load the desktop page in Playwright and check for page errors.
4. **Stage the 4 changed files on the user's Mac** with the device bridge, into `/Users/jeremychen/Error Log/Recall iPad app/`:
   `index.html`, `sw.js`, `desktop.html`, `version.json`.
   ⚠️ The bridge can serve a stale cached copy if you re-stage from the same container path. **Always copy into a NEW folder under `/mnt/user-data/outputs/` (e.g. `recall-web-v133`) before committing**, then check on the Mac with `device_bash` (`cat version.json`).
5. **The user drags those 4 files onto https://github.com/whisz12/Recall/upload/main and commits.**
6. **Verify:** `curl https://raw.githubusercontent.com/whisz12/Recall/main/version.json` should show the new build. (github.io itself isn't reachable from the container; raw.githubusercontent.com is.)
7. Tell them: Mac → **Recall → Check for Updates…** → **Restart now**; iPad → close fully and reopen.

`download.html` and `README.md` only need re-uploading if they change.

### When the desktop app itself must be reinstalled (rare)
The self-update only replaces the **page**. If a change needs new code in `main.js` / `preload.js`, or new bundled libraries or fonts:
1. Raise `MIN_SHELL` in `tools/release.py` to the new version, and bump `"version"` in `app/package.json` to match.
2. Rebuild and package both apps (§5), and send the user `Recall-mac.zip` and `Recall-windows.zip`.
3. They make a new **GitHub Release** (tag `vX.Y.Z`) and attaches both zips **with exactly those names**. Normal uploads are capped at 25 MB; releases aren't. You can pre-fill the release page with `https://github.com/whisz12/Recall/releases/new?tag=vX.Y.Z&title=...&body=...` in the built-in browser.
4. Apps older than `MIN_SHELL` show "needs a one-time reinstall" instead of half-updating.

## 5. Building the desktop apps

Electron **33.4.11** via `npx @electron/packager`, run from `app/`.

**Mac (arm64):**
```
npx @electron/packager . "Recall" --platform=darwin --arch=arm64 --electron-version=33.4.11 --icon=icon.icns --out=dist --overwrite \
  --app-bundle-id=com.jacob.errorlog --app-category-type=public.app-category.education --darwin-dark-mode-support --app-version=X.Y.Z \
  --extend-info=extra.plist --ignore='^/node_modules' --ignore='^/dist' --ignore='^/icon.png' --ignore='^/extra.plist' --ignore='^/icon.ico' --no-prune
```
Then ad-hoc sign it with **rcodesign** (apple-codesign 0.29.0, Linux musl build from GitHub releases): `rcodesign sign Recall.app`. Then `zip -qry Recall-mac.zip Recall.app` (keep the symlinks).

**Windows (x64):**
```
npx @electron/packager . "Recall" --platform=win32 --arch=x64 --electron-version=33.4.11 --icon=icon.ico --out=dist --overwrite --app-version=X.Y.Z \
  --win32metadata.ProductName=Recall --win32metadata.CompanyName=Jacob --win32metadata.FileDescription=Recall \
  --ignore='^/node_modules' --ignore='^/dist' --ignore='^/icon.png' --ignore='^/extra.plist' --ignore='^/seed' --ignore='^/icon.icns' --no-prune
```
Copy `dist/Recall-win32-x64` into a folder called `Recall`, then `zip -qry Recall-windows.zip Recall`.

Notes:
- Mac title bar: `hiddenInset` with traffic lights at (18, 19). Windows: `titleBarOverlay`. `winSetup()` swaps ⌘ for Ctrl in on-screen text.
- **The sidebar is a window drag region** (`-webkit-app-region: drag`). Anything clickable in it that isn't a `<button>` needs `-webkit-app-region: no-drag`. Forgetting this once broke the search box on Mac.
- A fresh Windows library starts empty. The Mac version can seed from `seed/`.
- To test the updater for real: `npm i electron@33.4.11` (Linux) and run under `xvfb-run` with `RECALL_UPDATE_URL=http://127.0.0.1:PORT/` pointing at a local folder holding `version.json` + `desktop.html`.

### How self-update works (`app/main.js`)
- Every page carries `<!-- recall-build:YYYYMMDDHHMMSS min-shell:X.Y.Z -->` right after the doctype.
- On launch (+6 s), every 3 h, and on window focus after 1 h: fetch `version.json`. If it's newer and `minShell` is satisfied, download `desktop.html`, check its stamp, and copy the bundled assets plus the new page into `userData/app-updates/<build>/`. Then send `update-status: ready` and the page shows the bar.
- `pagePath()` loads the newest valid update folder (or the bundled page). Old folders are cleaned up. "Restart now" just reloads the window from the new page, and localStorage is kept (same file:// origin).
- The Mac menu has **Check for Updates…**. The page has **Themes → Updates → Check for updates**.
